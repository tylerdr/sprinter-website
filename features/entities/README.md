# Entity System - Dot-Slug Architecture with Workspace Standardization

The MortgageQ entity system provides a sophisticated framework for managing structured data with tool integration, workspace patterns, and schema validation using dot-slug naming conventions.

## Architecture Overview

### Core Concepts

1. **Entities**: Structured data containers with JSON state and schema validation
2. **Entity Types**: Templates that define schema, UI configuration, and tool mappings
3. **Workspaces**: Root entities that contain and organize related entities (one per chat)
4. **Artifacts**: Persistent outputs generated by tools and attached to entities
5. **Dot-Slug Naming**: Hierarchical naming using dots (e.g., `loan.scenario`, `lead.contact`)

### Database Schema

```sql
-- Entity types define schemas and tool mappings
entity_types (
  slug text primary key,           -- e.g., "loan.scenario"
  namespace text,                  -- e.g., "loan"
  name text,                       -- Human-readable name
  schema_json jsonb,               -- JSON Schema for validation
  ui_config_json jsonb,            -- UI display configuration
  entity_mapping jsonb,            -- Tool mappings and constraints
  is_workspace boolean,            -- True for workspace containers
  version int
)

-- Entities are instances of entity types
entities (
  id uuid primary key,
  type_slug text,                  -- References entity_types.slug
  full_slug text,                  -- Auto-generated: namespace.type_slug
  namespace text,                  -- Extracted from type
  workspace_id uuid,               -- Parent workspace (self-reference)
  is_root_workspace boolean,       -- True for chat workspaces
  state_json jsonb,                -- Current entity state
  state_version int,               -- Optimistic concurrency control
  user_id uuid,                    -- Owner
  tenant_id bigint,                -- Multi-tenancy
  title text,
  created_at timestamptz,
  updated_at timestamptz
)

-- Artifacts are tool outputs attached to entities
ai_artifacts (
  id uuid primary key,
  entity_id uuid,                  -- Parent entity
  kind text,                       -- e.g., "eligibility_report"
  title text,
  data_json jsonb,                 -- Artifact content
  meta_json jsonb,                 -- Metadata
  created_at timestamptz,
  updated_at timestamptz
)
```

## Usage Examples

### 1. Basic Entity Operations

```typescript
import {
  createOrAttachEntityAction,
  getEntityAction,
  applyEntityPatchAction
} from '@/features/entities';

// Create a loan scenario entity
const { entityId } = await createOrAttachEntityAction({
  typeSlug: 'loan.scenario',
  title: 'Purchase Scenario',
  initialState: {
    borrower: { fico: 750, dti: 0.35 },
    property: { value: 500000, type: 'single_family' },
    loan: { amount: 400000, purpose: 'purchase' }
  }
});

// Update entity state
await applyEntityPatchAction({
  entityId,
  patch: {
    borrower: { fico: 780 } // Partial update
  }
});

// Retrieve entity
const entity = await getEntityAction(entityId);
```

### 2. Workspace Pattern (One Root Entity Per Chat)

```typescript
import {
  getOrCreateChatWorkspaceAction,
  addEntityToChatWorkspaceAction,
  getChatWorkspaceAction
} from '@/features/entities';

// Initialize chat workspace
const { workspaceId, isNew } = await getOrCreateChatWorkspaceAction({
  chatId: 'chat-123',
  workspaceType: 'loan.scenario',
  title: 'Client Consultation'
});

// Add entities to workspace
await addEntityToChatWorkspaceAction({
  chatId: 'chat-123',
  entityTypeSlug: 'lead.contact',
  title: 'John Doe',
  initialState: {
    firstName: 'John',
    lastName: 'Doe',
    email: 'john@example.com'
  }
});

// Get full workspace
const workspace = await getChatWorkspaceAction('chat-123');
```

### 3. Tool-Entity Integration

```typescript
import { runToolWithWorkspaceAction } from '@/features/entities';

// Run tool with automatic entity management
const result = await runToolWithWorkspaceAction({
  slug: 'marketplace-search',
  values: { /* tool input */ },
  chatId: 'chat-123',
  expectedEntityType: 'loan.scenario', // Optional - auto-detected from tool mappings
  createEntityIfMissing: true,
  persist: true,
  validateAccess: true
});
```

### 4. Entity Registry and Schema Validation

```typescript
import { entityRegistry, validateEntityState } from '@/features/entities';

// Initialize registry
await entityRegistry.initialize();

// Get entity type
const entityType = entityRegistry.getEntityType('loan.scenario');

// Validate state
const validation = validateEntityState('loan.scenario', {
  borrower: { fico: 750 },
  property: { value: 500000 }
});

if (!validation.valid) {
  console.log('Validation errors:', validation.errors);
}
```

## Entity Types and Namespaces

### Built-in Namespaces

- **`workspace`**: Root workspace containers
- **`loan`**: Loan-related entities (`loan.scenario`, `loan.application`)
- **`lead`**: Lead management (`lead.contact`, `lead.activity`)
- **`analysis`**: Analysis results (`analysis.document`, `analysis.income`)

### Creating Custom Entity Types

```typescript
const entityType = {
  slug: 'custom.entity',
  name: 'Custom Entity',
  namespace: 'custom',
  schema: {
    type: 'object',
    properties: {
      field1: { type: 'string' },
      field2: { type: 'number' }
    }
  },
  entityMapping: {
    toolMappings: {
      'my-tool': {
        reads: ['field1'],
        writes: ['field2'],
        required: ['field1']
      }
    }
  }
};

entityRegistry.registerEntityType(entityType);
```

## Tool Integration

### Tool-Entity Mappings

Entity types can specify which tools can read/write specific fields:

```json
{
  "entityMapping": {
    "toolMappings": {
      "marketplace-search": {
        "reads": ["borrower", "property", "loan"],
        "writes": ["eligible_lenders", "missed_lenders"],
        "required": ["loan.amount", "borrower.fico"]
      }
    }
  }
}
```

### Access Control

The system automatically validates tool access:

```typescript
// Check if tool can read from entity
const canRead = entityRegistry.canToolReadFromEntity(
  'marketplace-search',
  'loan.scenario',
  'borrower.fico'
);

// Check if tool can write to entity
const canWrite = entityRegistry.canToolWriteToEntity(
  'marketplace-search',
  'loan.scenario',
  'eligible_lenders'
);
```

## Schema Validation

### JSON Schema Support

Entity types use JSON Schema for validation:

```json
{
  "type": "object",
  "properties": {
    "borrower": {
      "type": "object",
      "properties": {
        "fico": { "type": "integer", "minimum": 300, "maximum": 850 },
        "dti": { "type": "number", "minimum": 0, "maximum": 1 }
      },
      "required": ["fico"]
    }
  }
}
```

### Runtime Validation

```typescript
// Validation happens automatically on entity updates
await applyEntityPatchAction({
  entityId,
  patch: { borrower: { fico: 850 } },
  validateSchema: true // Default: true
});
```

## Migration and Database Functions

### SQL Functions

- `generate_full_slug(type_slug, namespace)` - Creates dot-notation slugs
- `create_workspace_entity(user_id, tenant_id, title, workspace_type)` - Creates workspace
- `attach_entity_to_workspace(entity_id, workspace_id)` - Links entities

### Migration Process

1. Apply database migration: `20250917190000_entity_dot_slug_enhancements.sql`
2. Update application code to use new entity actions
3. Initialize entity registry in your application startup

## Performance Considerations

- **Caching**: Entity registry caches type definitions
- **Optimistic Concurrency**: Version-based conflict resolution
- **Lazy Loading**: Entity types loaded on-demand
- **Indexing**: Full-text search on slugs and namespaces

## Best Practices

1. **Use Namespaces**: Organize entity types by domain (loan, lead, analysis)
2. **Workspace Pattern**: One root entity per chat for organization
3. **Schema Validation**: Always define and validate entity schemas
4. **Tool Mappings**: Explicitly define tool-entity relationships
5. **Access Control**: Use permission validation for security
6. **State Management**: Use patches for partial updates
